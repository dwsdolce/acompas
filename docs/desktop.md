# Building the desktop app (Electron)

The Electron mode is configured in this project and the icons are generated by
`yarn install`, so there is no extra setup: the prerequisites in
[Getting started](../README.md#getting-started) are the whole list.

Electron builds only ever produce a package for the machine you are on —
electron-builder does not cross-compile a macOS `.dmg` from Windows, or the
reverse.

## Current state per platform

| Host | Status | Output |
|---|---|---|
| **macOS** | Configured and released. Signing and notarization via `packaging/build_mac`. | `.dmg` |
| **Windows** | Configured, not yet released. | NSIS installer + portable `.exe` |
| **Linux** | Uses electron-builder's defaults — no `linux` block is set. | electron-builder default |

Icons need no configuration on any platform. Quasar points electron-builder at
`src-electron/electron-assets/icons/icon` and lets it pick the extension per
platform — `icon.ico` on Windows, `icon.icns` on macOS — and `yarn icons`
generates both.

Windows packaging has not been through a release yet, so treat the first
`yarn build:electron` on Windows as the thing that proves it. Publishing a
Windows build is still an open roadmap item.

## Build commands

```bash
# Build and run the Electron app in debug mode
npx quasar dev -m electron

# Build the Electron app for production
npx quasar build -m electron

# The same, through the package scripts
yarn build:electron        # production build
yarn build:electron:dev    # development build
yarn build:electron:prod   # production build (explicit)
```

To build only the unpackaged app — which is what the end-to-end tests launch,
and much faster than producing an installer:

```bash
npx quasar build -m electron -s
```

That writes `dist/electron/UnPackaged`.

## Signed and notarized macOS builds

> macOS only.

`quasar build -m electron` produces an unsigned application, which is what you
want locally: it launches without Gatekeeper interfering. Distributing one to
another Mac needs it signed with a Developer ID, notarized by Apple and stapled,
which `packaging/build_mac` does:

```bash
packaging/build_mac        # signs, notarizes and staples the .dmg
packaging/build_mac app    # stop after the .app, no disk image
```

The Developer ID and the notarytool keychain profile are read from
`~/.config/macsign.env`, outside the repository, so nothing secret is committed
and there is one place to edit them:

```bash
export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)"
export APPLE_KEYCHAIN_PROFILE="notarytool-profile"
export CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)"
export NOTARY_PROFILE="notarytool-profile"
```

Store the notary profile once with `xcrun notarytool store-credentials`. Without
the file the script says so and builds unsigned, so it works for anyone who is
not the maintainer.

Both the application and the disk image make the trip to Apple: electron-builder
notarizes and staples the `.app`, and the script then notarizes and staples the
image around it. The image is what someone downloads, and a stapled ticket is
what lets Gatekeeper clear it without a round trip to Apple.

## Troubleshooting

### The app exits immediately with no window

If Electron exits with no window, or the main process fails with `The requested
module 'electron' does not provide an export named 'BrowserWindow'`, check for
`ELECTRON_RUN_AS_NODE` in the environment:

```bash
echo $ELECTRON_RUN_AS_NODE            # anything but empty is the problem
```

```powershell
$env:ELECTRON_RUN_AS_NODE             # PowerShell
```

It makes the Electron binary run as plain Node, so there is no `app`, no
`BrowserWindow` and no window. **VS Code's plugin host exports it and every shell
it spawns inherits it**, so a terminal inside an editor can have it set even
though no dotfile does — which makes this most likely to bite exactly when you
are working in an IDE.

`packaging/build_mac` unsets it. Otherwise:

```bash
env -u ELECTRON_RUN_AS_NODE npx quasar dev -m electron   # bash / zsh / Cygwin
```

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE                     # PowerShell
```

### Stale state after an update

Delete local storage in the browser (or the app's user data directory) after an
app update.
